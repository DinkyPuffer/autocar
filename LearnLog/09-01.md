项目学习工作日志（嵌入式双核小车悬崖防跌落系统开发）

一、 任务概述
本项目完成了基于 Hi3861（主控与传感器感知）与 STM32（底盘电机驱动）的双核协同小车悬崖防跌落系统。系统实现了悬崖边缘的检测、防跌落紧急倒车避障以及尾灯状态联动的全流程闭环控制。

二、 核心问题诊断与解决

1. 串口通信协议解析失步：
* 诊断：小车在平稳前进等周期性任务中运行正常，但遇到悬崖触发突发倒车时失效。原因是 STM32 串口中断服务函数缺乏严谨的状态机校验，在突发指令下引发帧头帧尾错位。
* 解决：在 STM32 的 USART1_IRQHandler 中重构了 3 阶段严格校验机制，只有依次满足帧头（0xFC）、数据位（4字节）和帧尾（0xFD）时才判定为有效指令；同时将 PWM 刷新逻辑与接收标志位绑定，实现按需更新。


2. 底层 PWM 驱动逻辑反向：
* 诊断：触发悬崖检测时，尾灯正常点亮（证明 STM32 已成功接收倒车指令），但电机依然向前转动。排查发现 pwm.c 中的 Set_Pwm 函数在负速度处理时使用了 `7199 - myabs()` 占空比计算公式，导致输出波形颠倒。
* 解决：修正 Set_Pwm 逻辑，将转向控制（AIN/BIN 高低电平）与速度大小完全解耦，速度占空比统一采用 `myabs()` 绝对值赋值，恢复正确的电机反转能力。


3. 通信策略与速度参数优化：
* 优化：将小车前进和转弯速度降低至原来的 1/4（从 20 调整为 5），后退速度维持 -25，有效减小了高速前进产生的惯性；同时在 Hi3861 端引入状态枚举机，仅在运动状态切换时下发串口指令，消除了高频冗余数据对串口的轰炸。


4. 鸿蒙 SDK 接口编译报错：
* 解决：修复了 Hi3861 引脚初始化时的编译错误，将错误的上拉宏定义替换为 `hi_io.h` 对应的硬件层标准宏 `HI_IO_PULL_UP`。



三、 最终成果与验证

* 功能验证：小车在地面行驶至悬崖边缘时，红外传感器能够第一时间捕捉信号。Hi3861 顺利切入避障状态并下发指令，STM32 精准解析数据，后退尾灯瞬间点亮，小车执行 1 秒的稳健倒车及转向避障，整套系统响应迅速、运行平稳。
* 总结：通过本次项目，深入掌握了跨芯片串口通讯中的状态机防错设计、电机驱动 PWM 方向控制原理以及嵌入式多线程中的状态机按需通信机制。

一、 今日工作内容总结

1. 悬崖避障与控制逻辑优化
   - 在Hi3861主控端实现了基于强力反接制动（Plug Braking）的紧急刹车机制 `car_emergency_brake()`。在检测到悬崖信号的第一时间，向STM32下发短暂的反向脉冲信号（-50），有效抵消小车向前行驶的机械惯性，解决前冲过大问题。
   - 对避障控制流程进行重新梳理，形成了“触发检测 -> 紧急反接制动 -> 停顿缓冲 -> 带心跳保持的倒车避让 -> 转向规避 -> 恢复常态行驶”的闭环状态机。

2. 控制周期与通信实时性调优
   - 针对小车高速行驶时的“响应盲区”问题，测试并对比了不同的传感器轮询采样周期（从50ms提升至10ms/3ms）。
   - 深度分析了3ms超高频采样下的硬件瓶颈与系统影响：验证了160MHz主频的Hi3861在2~3ms轮询下CPU资源占用极低且GPIO读取无物理损耗；同时核算了115200波特率下6字节串口数据包的传输耗时（约0.52ms），确认了通信余量的安全性。

3. 双核协作与看门狗超时机制匹配
   - 针对高频控制下可能出现的通信中断与跑飞隐患，对STM32端的 `UART_Protocol_Control()` 做了同步匹配。
   - 重新计算并调整了STM32主循环的延时与串口超时看门狗阈值（`uart_timeout_cnt`），确保系统既能在高频控制下稳定刷新PWM，又能在发生串口断连时在100ms内紧急切断电机输出，保证控制安全性。

4. 硬件与干扰问题排查
   - 针对调试过程中出现的LED指示灯偶发闪烁（前灯绿光）现象进行了系统排查。确认了串口通信协议与NFC处理函数中仅包含尾灯控制（`R_led_mode` / `R_led_CLC`），排除了代码逻辑误触发的可能性。
   - 确定该异常为电机启动/急刹瞬间电源电压波动或电机高频干扰（EMI）导致的灯珠芯片瞬间复位，不影响核心控制逻辑。

二、 遇到的问题与解决方案

1. 问题：小车到达悬崖边缘时由于惯性容易滑出边缘。
   解决：新增 `car_emergency_brake()` 函数，利用电机反向脉冲提供60ms的反向阻尼，瞬间抵消向前动能。

2. 问题：提升Hi3861采样频率后，STM32端出现无法正常前进或通信超时误触发的情况。
   解决：理顺了Hi3861发送频率、STM32 `main.c` 轮询周期以及 `usart.c` 超时门限三者的匹配关系，恢复为系统最适配的稳定参数组合。
