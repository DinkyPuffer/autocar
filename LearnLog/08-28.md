二、 详细任务完成情况与代码实践

1. STM32实现NFC读卡驱动与校验
深入学习了NFC（PN532芯片）与Mifare S50卡片的通信机制。PN532支持ISO14443A协议，默认以115200bps波特率通过串口与STM32通信。卡片采用无源射频感应供电，当进入天线场强区域时被唤醒。

在代码实现层面，通过串口2循环向PN532发送唤醒指令与寻卡指令。具体寻卡指令为 00 00 FF 04 FC D4 4A 01 00 E1 00，其中 0x04 为包长度，0xFC 为长度校验，0xD4 0x4A 为寻卡命令标识。

串口接收中断服务函数 USART2_IRQHandler 负责解析应答数据。无卡时只返回6字节先导数据 00 00 FF 00 FF 00；当寻到卡时，串口接收25字节数据，帧头标识变为 0xD5 0x4B。代码中通过比对第19至22字节（UID区域）来识别特定卡号：
((0xB9==buf[19])&&(0x80==buf[20])&&(0x06==buf[21])&&(0x85==buf[22]))

通过手机NFC助手App预先读取出卡片UID（E3:D4:E9:33）并写入逻辑判断。当校验成功后，调用 FoundCard_Handler 函数反转小车车灯标志位 led_flag，控制LED交替亮灭，实现刷卡交互。

2. OpenHarmony系统调试 - OLED屏I2C字符与时钟显示
学习了I2C半双工总线通信原理，SDA数据线与SCL时钟线均通过上拉电阻接到3.3V。掌握了OpenHarmony提供的I2C API，包括 I2cInit（设备初始化）、I2cWrite（数据写入）、I2cRead（数据读取）及 I2cSetBaudrate（波特率设置）。

在 applications/sample/wifi-iot/app/ 下创建工程 7.0_I2c_Ssd1306，将驱动支持包中的 include 和 src 文件夹复制入内。配置工程级 BUILD.gn 构建静态库 I2c_Ssd1306，并在主 app/BUILD.gn 的 features 列表中取消注释 "7.0_I2c_Ssd1306:I2c_Ssd1306"。

编写主程序 I2c_Ssd1306.c，使用 osThreadNew 创建优先级为 osPriorityNormal 的 thread_1 线程。在任务逻辑中，先调用 SSD1306_Init() 初始化屏幕并调用 SSD1306_CLS() 清屏。利用 SSD1306_ShowStr 在第0行显示 "QST CAR"，第3行显示 "2025:10:08"。

在 while(1) 循环中实现逻辑时钟计数，每秒将 sec 递增，并处理秒转分、分转时的进位逻辑。利用 sprintf((char*)displayBuff, "%02d:%02d:%02d", hour, min, sec) 格式化字符串，并渲染到OLED第2行，实现实时数字时钟刷新。

3. OpenHarmony系统调试 - SHT20温湿度采集与信号量同步
学习了SHT20高精度温湿度传感器（测量范围及精度：±3%RH，±0.3℃）的I2C通信模式，重点掌握了CMSIS-RTOS2信号量（Semaphore）在任务同步中的应用。区别于互斥锁（Mutex）用于资源抢占与保护（初始值通常为1），同步信号量初始值设为0，专门用于“等待-唤醒”配合逻辑。

创建工程 8.0_Sht20，在 Sht20.c 中通过 osSemaphoreNew(4, 0, NULL) 创建最大计数值为4、初始计数值为0的信号量 sem1。

在Demo中创建了三个同等优先级（25）的线程：
Thread1（生产者）：循环调用 osSemaphoreRelease(sem1) 连续释放两次信号量，随后 osDelay(300) 休眠3秒。
Thread2与Thread3（消费者）：均调用 osSemaphoreAcquire(sem1, osWaitForever) 进入阻塞死等状态。

由于 Thread1 一次性释放了两个信号量，Thread2 和 Thread3 会被同时唤醒并同步执行。Thread2 唤醒后调用 SHT20_Init() 并通过 SHT20_ReadData(&temperature, &humidity) 触发I2C读数（换算公式处理内部温度与湿度ADC原始值），随后打印出浮点数格式的温湿度，Thread3 同步响应打印得到信号量提示。

配置 8.0_Sht20/BUILD.gn 构建静态库，并在总入口 app/BUILD.gn 中使能 "8.0_Sht20:Sht20"。使用 python build.py wifiiot 编译打包后通过串口助手成功观察到完整的同步日志输出。针对中文字符乱码问题，通过修改 VS Code 编码为 GBK 格式重新保存，使串口助手正常渲染中文提示。
