主要任务：硬件逻辑排查、串口通信协议对接及悬崖避障算法开发

一、 核心工作内容

红外传感器（TCRT5000）原理图分析与硬件逻辑修正：

分析了 TCRT5000 + LM393 比较器组成的双路红外巡线/避障电路。

修正了软件逻辑判定错误：确定在当前电路中，当红外被吸收/无反射（悬空/黑色）时，INA+ > INA-，输出为高电平 (1)；有反射（地面/白色）时输出为低电平 (0)。

悬崖防跌落避障算法设计与代码整合：

采用基于 CMSIS-RTOS2 的多任务线程框架，将 Hi3861 传感器采集与 UART2 发送至 STM32 的串口控制协议（0xFC 帧头，0xFD 帧尾）进行深度整合。

运行逻辑：小车默认保持前进 -> 检测到左/右悬崖信号（高电平）-> 触发反接急刹（抵消向前惯性）-> 倒车拉开安全距离 -> 原地转向避开悬崖 -> 恢复正常前进。

电机驱动死区调优与实际硬件联调：

解决串口正常收到调试信息但电机不转的死区问题（确定 PWM 在低占空比下无法克服电机静摩擦力）。

将前进 PWM 初始值从 5 逐步调优提升至 50，确保驱动电压跨过电机的起动门限。

调整转弯控制时序，将避障转向延时扩大 3 倍（至 0.9 秒），使小车能够在检测到边界后彻底转过安全角度。

二、 问题排查与心得总结

硬件原理图阅读的重要性：在编写嵌入式 GPIO 驱动时，必须严格参照电路原理图（比较器反相/同相端输入连接）来确定软件的有效电平，不能仅依赖经验或默认注释。

电机控制的实际物理特性：理论上的 PWM 线性输出在现实中受限于机械摩擦和驱动芯片压降，因此在设定基础速度时需要找到硬件系统的“起动死区阈值”，并针对不同速度动态调整急刹与反向脉冲参数。


日志主题：综合系统实验 - 蓝牙遥控小车实现与串口通信协同
【一、 今日任务概述】

任务名称：综合系统实验 - 蓝牙遥控小车

核心知识点：蓝牙远程通讯协议解析、Hi3861 与 STM32 跨芯片双串口通信、多任务与硬件引脚复用配置。

重点与难点：

重点：实现蓝牙无线指令（JDY-16 模块）的稳定接收与字符解析，完成小车前进、后退、左右转及停止等动作的响应。

难点：Hi3861 双串口（UART1 蓝牙模块通信、UART2 STM32 下层控制通信）同时启用的底层配置冲突解决及自定义跨芯片通信协议的编码实现。

【二、 具体实践与任务实现过程】

工程创建与结构重组：

在 OpenHarmony 的 app 目录下，复制基础工程 1.0_Hello_World 并重命名为 14.0_Bluetooth_control。

重构工程源码，将主 C 文件修改为 Control.c，清理无用旧代码，重新定义所需头文件及全局数据缓存区：

uint8_t uart_sendbuf[20]: 用于存放打包后发送给 STM32 的串口控制数据帧。

uint8_t bluetooth_flag[1000]: 用于接收蓝牙模块传入的指令数据。

跨芯片串口通信协议与运动控制逻辑编写（stm32motor_control）：

设计并实现发送至 STM32 从控板的底层数据协议帧结构（帧长 6 Bytes）：

帧头：0xFC

byte 1: 左轮方向（0-正转，1-反转）

byte 2: 左轮目标转速（幅值限制在 0 ~ 150 rad/s*100）

byte 3: 右轮方向（0-正转，1-反转）

byte 4: 右轮转速（幅值限制在 0 ~ 150 rad/s*100）

帧尾：0xFD

基于协议封装基础运动控制函数：

car_forward(): 前进（左右轮设定 100, 100）

car_backward(): 后退（左右轮设定 -150, -150）

car_left(): 左转（左右轮设定 -50, 150）

car_right(): 右转（左右轮设定 150, -50）

car_stop(): 停止（左右轮设定 0, 0）

蓝牙指令解析任务（car_mode_bluetooth）：

创建独立的 CMSIS-RTOS 任务，循环读取 UART1（蓝牙 JDY-16 模块）缓冲区。

实现字符控制映射：

'O' -> car_stop()（停止）

'W' -> car_forward()（前进）

'S' -> car_backward()（后退）

'A' -> car_left()（左转）

'D' -> car_right()（右转）

'I' / 'K' -> 自定义不同档位速控调速

每次处理完指令后，清空首字节缓存并通过 hi_sleep(50) 进行任务调度让出 CPU 资源。

硬件 IO 复用与双串口初始化（Control）：

配置 UART1（蓝牙通信）：GPIO_0 映射为 UART1_TXD，GPIO_1 映射为 UART1_RXD，波特率设置为 9600。

配置 UART2（STM32 通信）：GPIO_11 映射为 UART2_TXD，GPIO_12 映射为 UART2_RXD，波特率设置为 115200。

创建优先级为 25、栈大小为 4KB 的 OS 线程（car_mode_bluetooth），使用 APP_FEATURE_INIT(Control) 注册为应用启动入口。

系统级底层修改与编译构建配置：

修改工程 BUILD.gn 文件及全局 app 编译选项，确保构建系统仅包含 14.0_Bluetooth_control:Control 目标。

解决双串口并发初始化失效的底层问题：定位到源码路径 /vendor/hisi/hi3861/hi3861/app/wifiiot_app/src/app_main.c，将事件关联宏 APP_INIT_EVENT_NUM 修改为 7，确保 UART1 与 UART2 能正常并发工作。

运行 python build.py wifiiot 指令，成功完成系统固件的编译与烧写。

【三、 实验现象与测试验证】

上电后，Hi3861 串口打印 "ble uart OK!" 与 "uart OK!"，确认双串口成功初始化。

配合电池独立供电（保障电机驱动电流需求），成功使用移动端蓝牙 APP 连接小车上的 JDY-16 蓝牙模块。

通过蓝牙按键发送 'W'/'S'/'A'/'D'/'O' 等控制指令，Hi3861 正确接收并迅速打包 0xFC...0xFD 协议帧透传给 STM32 从控，STM32 解析后驱动双电机按照预定方向与转速平稳运行。
